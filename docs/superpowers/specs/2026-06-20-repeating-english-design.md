# Repeating English — дизайн v1

**Дата:** 2026-06-20
**Статус:** утверждён, готов к плану реализации

## Цель

Личный веб-тренажёр английского для русскоговорящего пользователя. Пользователь
повторяет задания на грамматику и слова столько, сколько нужно, чтобы добить
целевой скор по каждому правилу/слову. Ключевая особенность: повторяются не одни
и те же карточки, а **концепты** — на слабый концепт всегда выдаётся новое
задание из пула.

## Масштаб v1

Личный инструмент. Без авторизации, без серверной БД, без мультипользовательности.
Прогресс хранится локально в браузере. Контент готовится вручную (LLM-генерация —
следующая фаза).

## Стек

- React + TypeScript + Vite, статический SPA, без бэкенда.
- Контент: статические JSON-файлы в репозитории.
- Прогресс: `localStorage` (с возможностью перейти на IndexedDB при росте объёма).

## Модель данных

Иерархия: **Module → Concept → Exercise (пул)**.

- **Module** — модуль/категория. Группирует концепты. Пример: «Present Perfect»,
  «Топ-100 слов A2». Имеет уровень и порог скора `masteryThreshold` (дефолт 5).
- **Concept** — единица освоения: грамматическое правило ИЛИ слово/конструкция.
  Скор считается по концепту. Содержит пул заданий.
- **Exercise** — конкретный экземпляр из пула концепта. Концепт содержит много
  заданий, возможно разных типов. Система всегда выдаёт новое задание — одна и та
  же карточка не повторяется, пока есть альтернативы.

### Типы заданий

Один движок, поле `type` определяет рендер и проверку. Колонка «проверка»:
*авто* — однозначно верно/неверно; *гибрид* — точное/близкое(diff+самооценка)/далёкое.

| type | описание | проверка |
|------|----------|----------|
| `translate_ru_en` | перевод RU→EN, свободный ввод. Флагман для памяти, вес +2 | гибрид |
| `word_order` | русская фраза + банк английских слов вперемешку; собрать перевод тапами | авто |
| `choose_word` | выбор правильного варианта из списка | авто |
| `fill_gap` | один пропуск, короткий свободный ввод | гибрид |
| `multi_gap` | 2–3 пропуска в предложении, проверка по каждому | гибрид (по-пропускно) |
| `verb_form` | базовая форма в скобках → нужная форма (`He (go) ___` → `goes`) | авто (короткий ввод) |
| `match_pairs` | сопоставь английские слова с русскими переводами | авто |

`verb_form` заменяет прежний размытый «complete_construction»: сборка конструкций
покрывается `word_order`, формы — `verb_form`, множественные пропуски — `multi_gap`.

### Схема (ориентир)

```jsonc
// Module
{
  "id": "present-perfect",
  "title": "Present Perfect",
  "level": "B1",
  "masteryThreshold": 5,
  "conceptIds": ["pp-experience", "pp-just-already"]
}

// Concept
{
  "id": "pp-experience",
  "moduleId": "present-perfect",
  "title": "Present Perfect: опыт (ever/never)",
  "kind": "grammar",            // "grammar" | "vocab"
  "exerciseIds": ["ex-001", "ex-002", "..."]
}

// Exercise (поля зависят от type)
{
  "id": "ex-001",
  "conceptId": "pp-experience",
  "type": "translate_ru_en",
  "prompt": "Ты когда-нибудь был в Лондоне?",
  "accepted": ["Have you ever been to London?", "Have you ever been in London?"],
  "points": 2
}
```

Поля по типам:
- общие: `id`, `conceptId`, `type`, `prompt`, `points` (дефолт 1, для
  `translate_ru_en` — 2).
- `translate_ru_en`, `fill_gap`, `verb_form` → `accepted` (список эталонов).
  `verb_form` дополнительно несёт базовую форму прямо в `prompt` (в скобках).
- `choose_word` → `options` (варианты) + `accepted` (верный вариант).
- `word_order` → `bank` (слова; рендерер сам перемешивает при показе) +
  `accepted` (правильный порядок; может быть несколько валидных порядков).
- `multi_gap` → `prompt` с маркерами пропусков (`___`) + `gaps` — массив
  `{ accepted: [...] }` со списком эталонов по каждому пропуску.
- `match_pairs` → `pairs` (массив `{ en, ru }`).

### Прогресс (localStorage)

По каждому концепту:
- `score` — текущий скор (0 → `masteryThreshold`).
- `mastered` — достигнут ли порог.
- `recentExerciseIds` — недавно показанные задания (антиповтор).
- `errorCount` — счётчик ошибок (для итогов модуля).

Привязан к версии контента (`contentVersion`), чтобы при изменении JSON прогресс
не «протух» молча.

## Поток тренировки

1. Пользователь выбирает модуль.
2. На каждом шаге система выбирает **ещё не освоенный концепт** с приоритетом по
   наименьшему скору.
3. Из пула концепта случайно берётся задание вне окна недавних
   (`recentExerciseIds`, окно `min(размер пула − 1, 5)`) — так пул идёт по
   кругу в случайном порядке и одна карточка не повторяется подряд.
4. Пользователь отвечает → мгновенный фидбек → обновление скора концепта на экране.
5. Сессия идёт, пока пользователь не закроет либо пока модуль не добит.

## Механика скора

- Шкала концепта: `0 → masteryThreshold` (дефолт 5).
- Верный ответ: `+points` (1 по умолчанию, 2 за `translate_ru_en`).
- Ошибка: `−1`, не ниже 0.
- Концепт **освоен**, когда `score >= masteryThreshold`.
- Модуль **завершён**, когда все концепты освоены. Прогресс модуля: «X из Y
  концептов добито».

## Проверка ответов (гибрид)

Нормализация перед сравнением: регистр, пунктуация, лишние пробелы.

- **Точное совпадение** с одним из `accepted` → верно (+points).
- **Близкое** (отличие 1–2 слова по пословному diff) → показываем diff с
  ближайшим эталоном и спрашиваем самооценку «засчитать?». Да → верно, нет →
  ошибка.
- **Далёкое** → неверно (−1), показываем эталон(ы).

Гибрид применяется к свободному вводу: `translate_ru_en`, `fill_gap`,
`multi_gap` (по каждому пропуску отдельно). Типы с однозначным ответом —
`word_order`, `choose_word`, `verb_form`, `match_pairs` — проверяются
**автоматически** (для `word_order` сверяем собранный порядок со списком
валидных `accepted`).

Diff подсвечивает расхождение с эталоном — это обучающий момент.

## Экраны

1. **Главная / список модулей** — карточки модулей с прогрессом «X/Y концептов» и
   уровнем.
2. **Тренировка** — текущее задание (рендер по типу), поле ответа/варианты, кнопка
   проверки, фидбек с diff, текущий скор концепта.
3. **Итоги модуля** — сводка по завершении: какие концепты давались тяжело (по
   числу ошибок).

## Компоненты (границы)

- **Content loader** — читает JSON, валидирует схему, отдаёт модули/концепты/задания.
- **Progress store** — чтение/запись прогресса в localStorage, привязка к
  `contentVersion`.
- **Scheduler** — выбор следующего концепта и задания (приоритет + антиповтор).
- **Answer checker** — нормализация, точное/близкое/далёкое сравнение, diff.
- **Exercise renderers** — по одному на тип задания, общий интерфейс.
- **Scoring** — обновление скора концепта и статуса модуля.

Каждый компонент тестируется независимо: scheduler и checker — чистые функции над
данными, store изолирует localStorage.
